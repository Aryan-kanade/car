Fix the before/after slider drag jank. I've read the component — there are two concrete causes:

## Root causes of the lag

1. **`transition-all duration-300` on the handle line** (`src/components/BeforeAfterSlider.jsx:87`) — the hover-growth transition also applies to the `left: ${position}%` inline style, so every drag position change animates over 300ms → the handle visibly trails the cursor ("laggy")
2. **React re-render on every pointermove** — each `setPosition` re-renders the whole component including both Placeholder subtrees at pointer-event frequency (60–120+ Hz) → stutter

## The fix (imperative drag, zero re-renders)

1. **Ref-driven imperative updates during drag**: on pointerdown/move, write `line.style.left` and `beforeLayer.style.clipPath` directly via refs (with `requestAnimationFrame` coalescing) — **zero React re-renders while dragging**
2. **Scope the transition**: replace `transition-all` on the line with `transition-[width]` so only the hover growth animates, never the position
3. **State sync only at rest**: `setPosition` runs once on pointerup (and from the keyboard input) so the accessible range input mirrors the final value; mid-drag, the DOM is the source of truth
4. Labels' opacity still tied to position — update them imperatively too (same rAF pass), keeping them smooth

Result: the handle tracks the pointer 1:1 with no trailing animation, and the clip sweep is GPU-composited with no React work in the hot path. One-file change.
